# 수능형 영어 영역 문제지(hwpx) 만들기

역할 분담과 공통 규칙은 프로젝트 루트 `AGENTS.md`. 이 스킬은 Claude(출제·조판) 쪽 절차다.
**그림·도표는 항상 오른쪽 패널 Codex가 image gen으로 만든다. Claude는 그림을 직접 그리지 않는다.**
원본은 **양식만** 따른다. 평가원 문항·지문은 옮기지 않고 새로 출제한다.

순서 요약: **예산표 읽기 → 쓰면서 `budget.py check` → 넘침 0 → verify·교차 풀이 → build 한 번 → 검수.**

## 1. 분량 예산 먼저 — 쓰기 전에 (`tools/budget.py`)
**레이아웃은 쓰기 전에 정한다. 조판(한글)을 돌려 가며 분량을 맞추지 않는다.**
- `reference/budget.md` (= `PY tools/budget.py plan` 결과)를 먼저 읽는다. 칸마다
  칸 높이, 원본 여백, 원본 구성(발문/영어/보기/각주 줄 수), **지문 줄 상한과 낱말 목표**가 있다.
  - 지문 낱말 목표 = 줄 상한 × 10.4. 원본 밀도로 쓰려면 원본 여백이 0 근처인 칸은 상한을 꽉 채우고,
    여백이 큰 칸(예: 29번 236 pt)은 원본처럼 비워 둔다.
  - 발문은 원본과 같은 줄 수로(한국어 1줄 ≈ 28자). 1단 보기는 한 줄(영어 ≈ 55자, 한국어 ≈ 26자),
    2단 보기는 영어 ≈ 24자 / 한국어 ≈ 12자, 3단은 그 2/3, 5단은 숫자·짧은 낱말만.
  - 원본 구성과 다르게 쓰면(예: 발문 2줄, 각주 추가) 그만큼 지문 줄을 뺀다: 발문 1줄 ≈ 16 pt, 지문 1줄 16.1 pt,
    보기 1줄 17.3 pt, 각주 ≈ 14 pt.
- 쓰는 중·쓴 직후: `PY tools/budget.py check` — 한글 없이 1초 만에 원고 전체를 줄바꿈 계산해서
  칸마다 예상 여백과 판정(OK / 넘침 / 짧음)과 더하거나 뺄 낱말 수, 두 줄 넘는 보기·넘치는 각주 경고를 낸다.
  **넘침·경고가 0이 될 때까지 원고를 고친 뒤에만 build.py 를 돌린다.** (예측 오차 평균 1.6 pt, 최대 약 7 pt)
- 한 줄짜리 발문이 몇 글자 차로 두 줄이 되면, 원본처럼 그 문단만 자간을 좁힌다: `('q', "...", {"sp": -10~-15})`
  (check 가 sp 를 반영해 다시 계산한다).
- 엔진 문단 모양(줄 간격·여백)을 바꿨으면 빌드 후 `PY tools/budget.py fit` 으로 높이 모델 계수를 다시 맞추고
  `PY tools/budget.py plan` 으로 예산표를 다시 만든다. `calib` 는 예측 오차만 본다.

## 1-1. 출제 — `problems/exam.py`
- 형식은 파일 상단 docstring. 블록: `q` 발문, `p`/`p0` 지문, `pl` (A)(B)(C) 단락, `fn` 각주, `ch` 보기(1·2·3·5단),
  `emo`/`ord`/`ab` 특수 보기, `speaker`, `fig`, `tbl10`, `notice`, `letter`, `box`, `arrow`, `summary`.
- 서식 태그 `<u> <i> <b> <blank:n> <ublank:(A)>`. 발문의 영어 낱말은 자동으로 Times New Roman.
- 원본과 같은 유형 순서·배점(3점: 12·13·14·24·30·32·34·37·39·41) — 합 100점. 정답 ①~⑤ 각 9개.
- 듣기 1–16번은 `script=[(화자, 대사)]` 필수(17번은 16번 담화). 응답 문항은 마지막 대사를 빈칸("")으로.
- 분량은 1단계 예산표대로. 문항 하나를 쓸 때마다 `budget.py check` 로 그 칸을 확인하며 쓴다.

## 2. 검증
- `PY problems/verify.py` — 구성·배점·분포, 어법/어휘 밑줄 5곳, 삽입 위치 5곳, 순서 정답, 6·10·25번 재계산, 대본.
- 교차 풀이: `PY tools/answers.py` 가 만든 `build/solve_sheet.txt`(정답 없음)를 Codex에게 풀게 해서
  `build/codex_solve.txt` 를 받고, `verify.py` 를 다시 돌리면 불일치 문항이 나온다. 불일치·이의는 문항을 고쳐 해소.

## 3. 그림 — Codex에게 image gen으로
듣기 4번 그림, 25번 도표. `figures/FIGURE_SPEC.md` (예: templates) 작성 → `herdr agent prompt <codex> "...image gen으로..."`.
출제 직후 보내 조판과 병렬로. 도착 후 검수: 철자, 개수, 도표 수치와 막대 비율.

## 4. 조판 — `PY tools/build.py`
- **본문을 흘리지 않는다.** 쪽마다 빈 문단 하나에 머리말·꼬리말·단 구분선과 함께,
  각 문항(또는 묶음 지시문)을 원본 PDF에서 잰 y 위치의 **고정 칸**(쪽 기준 절대 위치 표, 폭 = 단 폭)으로 놓는다.
  → 한 문항이 길어져도 그 칸만 늘어나고, 다음 문항·다음 쪽은 밀리지 않는다.
- 칸 위치 = 원본 글자 위치 − (우리 글자 위치와 칸 위의 차이). 이 차이를 `build/offsets.json` 에 저장해 1~2회에 0.1 pt 로 수렴.
- 결과 확인: `PY tools/compare.py` (항목 56개 위치 대조, 1 pt 넘으면 `<--`),
  `PY tools/slack.py` (문항별 끝 여백 원본 대비). 1단계 check 를 통과했으면 여기서 고칠 일은 거의 없다.
  여기서 어긋나면 원고보다 예측 모델이 틀린 것 → `budget.py fit` 후 원인(새 블록 종류 등)을 features() 에 반영.

## 알려진 함정 (tools/ 에 반영됨)
1. **한글 장평**: 원본 본문 한글 폭 10.56 pt(11.2 pt의 94 %) → 장평 95, 자간 −1. 100 이면 줄마다 넘친다.
2. **영문 공백**: charPr `useFontSpace="1"` 이어야 Times New Roman 공백(0.25 em). 0 이면 한글 공백 폭으로 계산되어 줄당 5자씩 덜 들어간다.
3. **영문 크기**: 한 글자 모양에 한글 11.2 pt + 영문 상대 크기 109 %(=12.2 pt). 줄 간격 %는 기준 크기(11.2)로 계산된다.
4. **발문 줄 간격 150 %**(번호 13.2 pt 기준), 보기 155 %(1쪽 오른쪽 단만 149 %), 지문 144 %.
5. **본문 아래 경계**는 원본 1067.2 보다 6 pt 아래(마지막 줄 줄 간격 여백 자리), 꼬리말 위치는 그대로.
6. **한글 프로세스가 남으면** 다음 COM 저장이 `RPC_E_SERVERFAULT` 로 실패한다. 창 제목 없는 `Hwp` 프로세스(자동화가 띄운 것)를 종료하고 다시 실행.
7. HFT 글꼴은 PDF에서 Type3(`T1`…)로, 한글 낱말 사이 공백이 추출되지 않는다 → 측정은 공백을 지우고 비교.
8. 수학 빌더의 함정(글꼴 표 순서, `Clear(3)` 금지, `.ps1` ASCII 등)도 그대로 해당.
